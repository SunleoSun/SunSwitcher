# Autocomplete UI and caret anchoring

## Current boundary

`src/windows/caret_locator.rs` owns discovery of an on-screen text-caret anchor. It returns a typed `CaretAnchor` with screen-space coordinates, caret height, and the backend that produced it. Completion policy and ranking do not belong here.

The current caret discovery order is:

1. UI Automation `TextPattern2::GetCaretRange`; the focused UIA element is tried first, then up to eight raw-view ancestors, then a bounded raw-view descendant search (depth 8 / 128 elements) because browsers, terminals, and composite editors may expose the text provider deeper in the accessibility subtree;
2. UI Automation `TextEditPattern`, converted through its inherited `TextPattern`, with the same focused/ancestor/bounded-descendant discovery;
3. UI Automation text selection, including adjacent-character recovery for degenerate caret ranges;
4. MSAA `OBJID_CARET` + `IAccessible::accLocation`, tried first on the foreground GUI thread's focused HWND and then on the top-level foreground HWND, before classic Win32 caret discovery;
5. Win32 `GetGUIThreadInfo` + `ClientToScreen` for classic caret-owning controls.

`CaretLocator::locate()` remains the preferred anchor path used by the live autocomplete popup. If UIA/MSAA/Win32 cannot expose a caret while suggestions are active, production now uses `fallback_anchor()` as a final fail-soft placement: current pointer first, foreground-window geometry second. That fallback is captured once for the active suggestion session and is not recomputed every frame, so the popup does not chase the mouse; a subsequently discovered real caret immediately takes ownership again.

## Placement

`popup_placement` places the popup below the proven caret with a small gap, clamps it to the nearest monitor work area, and flips above the caret if there is insufficient vertical space below. UIA caret ranges that expose no rectangle are recovered from the adjacent character range so Chromium/Electron-style degenerate carets can still produce screen geometry. Caret discovery and popup placement remain separate behaviors.

## egui popup

`src/windows/autocomplete_popup.rs` owns the runtime suggestion window. It runs a borderless, taskbar-hidden, always-on-top egui/Glow suggestion child viewport with `active=false` and explicit opaque native composition. The root SunSwitcher viewport is the canonical interactive Clipboard Manager surface: while the manager is hidden the root is parked as a visible 1x1 off-screen event pump, and while the manager is open that same root native window is reconfigured into the normal decorated/resizable clipboard window. This deliberately avoids using a child viewport for SunSwitcher's primary interactive surface on Windows. Suggestion and notification child viewports remain declared through `show_viewport_deferred` while logically hidden so their native/Glow surfaces can be reused without first-frame desktop flashes. Suggestion updates repaint only when shared suggestion/selection state changes, and cached suggestion geometry avoids repeated caret lookup/root reconfiguration for identical state. With suggestions, `App::logic` prefers a real caret anchor and otherwise uses the frozen final fallback, then positions the child viewport through `popup_placement`. Rendering paints an opaque dark background, selected-row fill, and white text, with matching native clear color. Because this build intentionally uses `eframe` with `default-features = false`, the popup installs a Windows system font at startup (Segoe UI, then Arial/Tahoma as primary UI faces, plus Segoe UI Symbol and Consolas glyph fallbacks) into egui's proportional and monospace families; clipboard preview text uses the monospace family for code-like Unicode box and block glyphs. Native `mouse_passthrough` remains disabled for this Glow window because the Windows layered-style path produced an unpainted/transparent OpenGL client area. The popup owns the single dedicated Windows UI thread and single eframe/winit event loop used by SunSwitcher UI; `sunswitcher` drives this shared UI runtime from typed completion state and clipboard hotkeys.

The same UI owner runs a separate focusless transient notification child viewport. Notification lifetime is read from the live `SettingsStore` when each message is shown; the persisted default is three seconds and the typed range is 1-60 seconds. A newer message replaces the current one immediately and restarts the deadline using the current setting. Notification state never replaces or clears autocomplete state. While suggestions are visible, placement is recomputed from the current suggestion viewport x/y/height so the notification follows autocomplete as its rows and position change; monitor-aware `popup_placement` keeps it adjacent and flips sides when needed. Without application UI it anchors from the current caret/fallback. While the clipboard/settings UI is visible, notification placement instead prefers the root clipboard viewport geometry, so focus/caret discovery in the settings child cannot make a confirmed Pause/Ctrl+Pause notification disappear. Notification requests emit `[notification]` diagnostics with the concrete message before the child viewport is rendered.

## Input and hotkeys

The clipboard-manager settings entry point is the UI owner for application preferences, but the settings surface itself is a dedicated resizable native egui child viewport on the same single eframe/winit event loop rather than an `egui::Window` constrained inside the clipboard viewport. It has its own vertical `ScrollArea`, so additional settings remain reachable when the content exceeds the current viewport height. Its native Windows caption is styled through the same DWM caption/text color owner and constants as the main Clipboard window. The Settings viewport has its own taskbar entry; opening it explicitly unminimizes, shows, and focuses the existing viewport so a minimized settings window remains recoverable from both the gear button and the Windows taskbar. It edits the six configurable hotkeys, enables/disables autocomplete, same-layout autocorrections, and automatic cross-layout keyboard switching, and edits notification timeout. Feature checkboxes persist immediately; hotkey capture and notification timeout use explicit confirmation. Hotkey action controls use painter-drawn vector refresh/confirm/cancel geometry rather than font glyphs, avoiding missing-glyph `?` rendering on Windows UI fonts; the refresh control uses a conventional two-arrow circular form. Built-in egui keyboard zoom is disabled for the application UI so Ctrl+Plus/Ctrl+Minus chords remain available to the hotkey recorder instead of resizing the interface. The shared `SettingsStore` is updated only after SQLite persistence succeeds, so UI and runtime never become competing settings authorities. The settings viewport keeps a dedicated SQLite connection open for confirmations instead of reopening/reinitializing the database on every save, avoiding the multi-second busy/open stall that could leave the old shortcut live while the UI thread was blocked.

The default bindings remain plain Pause for correction Undo / selected-word forget and Ctrl+Pause for selected-word ignore, but both actions are now ordinary configurable `HotkeyAction` bindings. Windows may deliver physical Ctrl+Pause/Break as `VK_CANCEL` rather than `VK_PAUSE`; the typed hotkey contract canonicalizes that Ctrl-modified Windows identity to Pause before display/persistence, and runtime matching canonicalizes the observed event through the same contract. Settings therefore always renders `Ctrl+Pause`, while both Windows event forms execute the same binding even after the user assigns another shortcut and later records Ctrl+Pause again. Clipboard Current/Pinned, Completion Accept, Completion Next Word, Undo/Forget Word, and Ignore Word share one typed hotkey contract. The settings UI captures a new chord into a pending binding and requires explicit confirmation before persisting it; duplicate configured bindings are rejected. The low-level keyboard hook remains the primary capture source before ordinary SunSwitcher hotkey dispatch: modifier transitions remain in hook-owned keyboard state while listening, the first physical non-modifier key completes the pending chord, Esc cancels, and mouse clicks are not part of capture and do not cancel it. The focused settings viewport also keeps the proven short-interval `GetAsyncKeyState` fallback while listening because some focused native egui key paths do not reliably produce a usable hook capture. Both sources feed the same canonical `HotkeyCaptureHandle::observe_key_down` state machine, so the first completed observation moves the shared state to Pending and the other source cannot reinterpret or persist a second binding. The fallback snapshots physical state when recording starts, reports only newly pressed non-modifier keys with the current modifiers, and prioritizes `VK_CANCEL`/`VK_PAUSE` for Ctrl+Break. For runtime commands, the hook first matches the chord from its own physical key stream. Only when no configured command matches does it reconcile Ctrl/Shift/Alt/Win from Windows physical state and retry, so a SunSwitcher-owned modifier such as the suppressed Alt in Alt+Right is not erased before command resolution while stale layout-switch modifiers can still be cleared. `[hotkey-capture]` diagnostics record listening/cancel/captured transitions and whether the settings fallback supplied the winning observation. Runtime hotkey classification reads the shared live settings snapshot, so confirmed changes apply without restart and without SQLite I/O in the keyboard hook. Persistence returns a typed confirmed word outcome for forget/ignore operations, and only that outcome produces the transient notification with the concrete word.

The configurable hotkey contract reserves the fixed unmodified autocomplete controls (Esc, Up, Down, Delete). Settings conflict validation must reject those bindings for every configurable action so recording a shortcut cannot silently replace dismiss/navigation/delete behavior.
Runtime classification resolves configured commands against the modifier state observed by the low-level hook first. If that chord does not match, it reconciles Ctrl/Shift/Alt/Win from current Windows physical state and retries before ordinary key classification. This preserves actively held/suppressed command modifiers while still recovering from stale Alt+Shift/Win+Space layout-switch state. Unmodified Ignore/Undo bindings are queued out of the low-level hook immediately after their recognized keydown, while modified bindings wait until all chord modifiers are physically released; configurable chords such as Ctrl+W and Ctrl+Pause therefore never perform selection capture or replacement while Ctrl/Alt/Shift/Win remains held, and plain Pause does not depend on a later Pause key-up. Their recognized keydown preserves explicit mouse/Shift selection intent. Deferred selected-word actions use the existing clipboard-preserving explicit-selection capture when UI Automation exposes no selection; if explicit selection was proven but safe capture fails, the action fails closed instead of falling back to unrelated tracked text. Ignore still refreshes the lexical snapshot before rechecking the source, so suppressing valid source spellings such as jr or yt can immediately expose the corresponding cross-layout replacement and confirmed mutations emit the transient notification.

Live completion normally activates after three characters in the current token; after a completed word and trailing space, context-only sequence suggestions may remain active even with an empty current prefix. The production `sunswitcher` uses the live correction session, where strong unfinished wrong-layout prefixes can be replaced before boundary and completion is immediately refreshed from the corrected current prefix. An active live-prefix switch continues scoring later prefix evidence and reverses only when the opposite layout clears the stronger hysteresis margin, so close scores keep the visible layout stable. Unmodified Up/Down changes selection; unmodified **Tab** accepts the complete selected suggestion while Enter always passes through to the foreground application; Alt+Right accepts exactly the next word plus its separating space; unmodified Delete removes the selected prediction; and unmodified Esc dismisses. After a proven Alt+Right insertion, completion tracking advances to the accepted word, accepted words update user-word recency, the accepted context sequence is persisted into `text_history`, and sequence suggestions refresh immediately. After a proven automatic correction or Double Shift layout replacement of the previous word, completion context is refreshed to the replacement's canonical word instead of being left on the raw physical spelling or invalidated, so sequence suggestions can continue from the corrected/translated word. The remainder that was visible in the selected row before acceptance is protected as the prefix of the refreshed top row: ranking may extend it with newly predicted words, but may not change those already-visible words. Repeated Alt+Right therefore never inserts an unseen replacement word; Up/Down deliberately releases that protection and chooses another path. While completion is active, the physical Alt modifier used to form Alt+Right is owned by SunSwitcher: its down/up pair is suppressed from downstream hooks, while the internal keyboard state still records Alt so Right can resolve to `AcceptNextWord`. The accepted word is injected as Unicode only; no synthetic Alt release/repress is sent to the foreground application. Delete removes the row immediately from the current session; learned multi-word rows delete their exact `text_history` source, while single-word candidates persist a completion-only suppression so dictionary/user lexical authority is not destroyed. Keyboard runtime resolves a completion command before calling the downstream hook chain: handled command keydown/up pairs are SunSwitcher-only; only `Pass` from an inactive/non-consuming completion session is forwarded. Double Shift is a separate layout-switch command: two otherwise plain **physical** Shift taps within 400 ms trigger on the second Shift release; SunSwitcher/foreign injected keyboard transitions never participate in the gesture. A freshly owned typed layout span wins first because it is the strongest proof of the text immediately before the caret and avoids UIA/clipboard work; mouse or navigation selection invalidates that ownership before Double Shift. With no owned span, Double Shift first probes for an explicit selection with clipboard-preserving Ctrl+Insert, which is layout-independent and safe even when UI Automation exposes no selection. Shift+navigation, completed mouse-drag selection, and mouse double-click selection are tracked as typed user-selection intent. Existing explicit selections try Ctrl+Insert first, then Ctrl+Shift+C for terminal-style copy bindings; Ctrl+C is allowed only when UIA itself proves the selection, so it is not sent on intent alone. A second safe Ctrl+Insert probe distinguishes a selection that remained active from one that collapsed after copy; retained selections are replaced directly, while collapsed-at-start selections are reconstructed with the captured character count before the same Delete+Unicode replacement. Without an owned span or explicit selection, the previous-text fallback creates one bounded 64-character backward selection with physical Shift+Left instead of relying on application-specific Shift+Home semantics. After the synthetic Shift+Left, UIA-selected text is diagnostic only because browser UIA ranges can report a partial selection that is not the actual editable selection. The previous-text fallback uses clipboard-verified safe Ctrl+Insert first and then Ctrl+Shift+C; Ctrl+C is deliberately not used for this synthetic previous-text probe, so a terminal that refuses copy shortcuts fails closed instead of receiving an interrupt/printable C. If the synthetic backward selection remains active, SunSwitcher leaves that exact active chunk selected and applies the replacement as `leading copied text + transformed target + suffix` in one Delete+Unicode batch instead of collapsing the browser selection and selecting backward again. If copy collapsed the selection to the start, SunSwitcher advances by the captured caret-step count. From that restored original caret, SunSwitcher finds the trailing non-whitespace range (including layout punctuation), moves left across preserved trailing whitespace, selects only the target with Shift+Left, replaces it, and moves right across the preserved whitespace. This keeps capture/replacement relative to the proven original caret and avoids per-character clipboard probing. The owned `InputBuffer` layout span retains punctuation and trailing whitespace through Double Shift, remains owned after a successful transform for repeated switching in the opposite direction, and is replaced through the same Backspace+Unicode effect path used by automatic correction. Once ownership is unavailable, clipboard capture is used only after SunSwitcher has evidence of an explicit selection from UIA, keyboard Shift+navigation, mouse-drag, or mouse double-click selection intent, or has itself created the bounded Shift+Left backward selection. The selected/previous text transform returns both transformed text and target language. Alphabetic spans keep content-based target inference. Punctuation-only spans have no reliable language vote, so Double Shift derives the opposite EN/RU target from the foreground keyboard layout and uses explicit-target shifted surface mappings. Configured completion commands are applied on the trigger keydown instead of waiting for the user to release Ctrl/Shift/Win. The trigger key remains SunSwitcher-only; for modifiers already visible downstream, injection sends temporary modifier key-ups, writes the Unicode suffix/next-word text including spaces, and restores those modifier key-downs before returning, so Ctrl+W-style bindings feel immediate without turning inserted text into foreground command chords. Captured selections that remain active are replaced by clipboard-backed Ctrl+V paste instead of Unicode replay, so CRLF and multi-line content survive application-specific text input paths; terminal selections that collapse on copy are reconstructed from the proven caret anchor with Shift+Right before that same replacement. The previous-text fallback either replaces the retained active backward chunk directly or reconstructs the trailing non-whitespace range relative to the restored original caret via Left trailing offset, Shift+Left target selection, replacement, and Right trailing-whitespace restoration; line-start normalization and Ctrl+word-navigation are not used. Only after the text effect succeeds does SunSwitcher request the matching installed foreground keyboard layout through `WM_INPUTLANGCHANGEREQUEST`, so the next physical keystroke uses the same language as the converted text. Double Shift diagnostics use the `[double-shift]` diagnostic prefix and report tracked-span invalidation from mouse/navigation input, the chosen capture path, UIA observations before/after copy, clipboard source/range counts, and the final replacement path; the diagnostics describe observed state and never branch on application identity. The Double Shift editing effect is deferred from the second physical Shift key-up hook callback onto the hook thread message queue: the low-level hook never performs the multi-step SendInput/clipboard capture synchronously, so injected selection/copy events are processed only after the hook returns and Windows finishes the physical Shift release; a still-held physical Shift at deferred dispatch fails closed instead of editing under ambiguous modifier state. Backward chunk capture may include CRLF when the bounded selection crosses a line boundary; caret restoration treats each CRLF pair as one navigation step and still derives only the trailing non-whitespace target at the original caret. Synthetic text-range selection uses physical left Shift with extended Left/Right navigation rather than generic VK_SHIFT or line-start shortcuts; navigation-cluster keys keep the Windows extended-key identity. Safe probing uses physical left Control plus extended Insert (Ctrl+Insert); Ctrl+Shift+C is the terminal-style safe fallback; Ctrl+C is reserved for UIA-proven existing selections only, so neither unknown explicit-selection probing nor synthetic previous-text probing can degrade into terminal interrupt/printable C/С behavior. Any explicit input invalidation clears layout-span ownership even when that span came from a previous Double Shift replacement; navigation therefore cannot leave a stale transformed span eligible for a later gesture. A tracked span that exists but has no layout transform is dropped and Double Shift continues into the normal capture fallback instead of ending the gesture. Clipboard manager defaults are handled by the same Windows keyboard runtime: Ctrl+Shift+Num+ opens the text history window on the Pinned tab, and Ctrl+Shift+Num- opens it on the Current tab. The clipboard egui surface does not separately consume those legacy chords; configured bindings in the shared `SettingsStore` are the single runtime authority, so replacing a default shortcut also removes the old one immediately. The manager stores the foreground window captured at hotkey time and shows the root Clipboard Manager viewport with Current/Pinned tabs, case-insensitive filter, top-row numeric insert buttons, context-menu Pin/Unpin, and a settings view for hotkeys, feature toggles, and notification timeout. Text entries selected for insertion are first copied to the system clipboard and then pasted with Ctrl+V into the captured foreground window; insertion fails closed when no target exists or Windows refuses to focus it. The listener owns the resulting text-history/copy-count update so one manager action is not counted twice; guarded image copy-back updates its entry directly. These bindings remain defaults; confirmed settings changes replace them live through the shared `SettingsStore`.

## Clipboard manager window

The Clipboard Manager is rendered directly by the root eframe viewport rather than a dedicated child viewport. A show request mutates the shared `ClipboardManagerState`, preserves the original foreground target HWND while already visible, advances `serial` and the semantic `show_serial`, and requests repaint of `ViewportId::ROOT`. On the UI thread, `ClipboardManagerApp` observes that state; opening the manager reconfigures the root into a decorated/resizable 520x420 window, while closing or minimizing parks the same root as a visible 1x1 off-screen event pump so the single eframe event loop stays alive for tray/hotkey reopen and the remaining child viewports. Repeated Current/Pinned hotkeys while visible reassert `Minimized(false)`, `Visible(true)`, and focus on the root without replacing the originally captured insertion target. The confirmed failure was input-side: while the root Clipboard Manager viewport had focus, the low-level hook could observe Num+/Num- with stale Ctrl/Shift state and fail the configured binding match even though the physical chord was held; the focused-window fallback resolves the chord from GetAsyncKeyState and sends it through the canonical configured matcher. Clipboard hotkey recognition stays inside the low-level hook, but opening or switching the Clipboard Manager is deferred onto the hook thread message queue before calling the processor; the hook callback only records key-up suppression, queues the typed command plus captured target HWND, and returns immediately so UI dispatch cannot block subsequent physical keyboard events. Settings, autocomplete suggestions, transient notifications, and clipboard previews remain separate child viewports where their independent lifecycle is useful. Clipboard history list queries return the complete ordered text/image history using a lightweight summary projection; image BLOBs are loaded lazily for preview/activation. The manager keeps a dedicated read connection and caches the complete lightweight summary source until an explicit history/tab mutation; filter edits rebuild only in-memory matching indexes, and row rendering is virtualized. Current/Pinned tab switching remains owned by the configured global hotkeys, with no second hardcoded egui shortcut authority. The shared egui context disables both keyboard zoom shortcuts and egui's default Cmd/Ctrl+Q quit shortcut so configurable SunSwitcher bindings are never preempted by framework-global commands while any viewport has focus. While the Clipboard Manager itself is focused, its UI also polls the physical Windows key state and routes a newly pressed key through the same canonical configured clipboard-hotkey matcher; this focused-window fallback only acts when the requested tab differs, so a missed low-level modifier state cannot prevent Current/Pinned switching and no hardcoded second binding authority is introduced. Row activation, pinning, clear/clear-all, delayed preview, outer-corner preview resizing, tray behavior, title-bar styling, insertion target preservation, clipboard learning, and large-text Ctrl+V insertion retain their existing semantics.
