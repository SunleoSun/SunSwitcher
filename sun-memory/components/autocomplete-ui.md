# Autocomplete UI and caret anchoring

## Current boundary

`src/windows/caret_locator.rs` owns discovery of an on-screen text-caret anchor. It returns a typed `CaretAnchor` with screen-space coordinates, caret height, and the backend that produced it. Completion policy and ranking do not belong here.

The current caret discovery order is:

1. UI Automation `TextPattern2::GetCaretRange`; the focused UIA element is tried first, then up to eight raw-view ancestors, then a bounded raw-view descendant search (depth 8 / 128 elements) because browsers, terminals, and composite editors may expose the text provider deeper in the accessibility subtree;
2. UI Automation `TextEditPattern`, converted through its inherited `TextPattern`, with the same focused/ancestor/bounded-descendant discovery;
3. UI Automation text selection, including adjacent-character recovery for degenerate caret ranges;
4. MSAA `OBJID_CARET` + `IAccessible::accLocation`, tried first on the foreground GUI thread's focused HWND and then on the top-level foreground HWND, before classic Win32 caret discovery;
5. Win32 `GetGUIThreadInfo` + `ClientToScreen` for classic caret-owning controls.

`CaretLocator::locate()` remains the preferred anchor path used by the live autocomplete popup. If UIA/MSAA/Win32 cannot expose a caret while suggestions are active, production now uses `fallback_anchor()` as a final fail-soft placement: current pointer first, foreground-window geometry second. That fallback is captured once for the active suggestion session and is not recomputed every frame, so the popup does not chase the mouse; a subsequently discovered real caret immediately takes ownership again.

## Placement

`popup_placement` places the popup below the proven caret with a small gap, clamps it to the nearest monitor work area, and flips above the caret if there is insufficient vertical space below. UIA caret ranges that expose no rectangle are recovered from the adjacent character range so Chromium/Electron-style degenerate carets can still produce screen geometry. Caret discovery and popup placement remain separate behaviors.

## egui popup

`src/windows/autocomplete_popup.rs` owns the runtime suggestion window. It runs a borderless, taskbar-hidden, always-on-top egui/Glow suggestion child viewport with `active=false` and explicit opaque native composition, while the root SunSwitcher UI viewport stays parked as a 1x1 off-screen event pump when the clipboard manager is hidden. Suggestion updates repaint only when shared suggestion/selection state changes, and cached suggestion geometry avoids repeated caret lookup/root reconfiguration for identical state; however the child viewport callback is still reattached on each root UI pass while visible, because egui child viewports disappear if the deferred viewport is not shown again. With suggestions, `App::logic` prefers a real caret anchor and otherwise uses the frozen final fallback described above, then positions the already-live child viewport through `popup_placement`. Rendering paints an opaque dark background, selected-row fill, and white text, with matching native clear color. Because this build intentionally uses `eframe` with `default-features = false`, the popup installs a Windows system font at startup (Segoe UI, then Arial/Tahoma fallback) into egui's proportional and monospace families. Without an explicit font definition, egui still paints shapes but text glyphs are absent. Popup startup fails instead of silently showing a textless window if none of the supported Windows fonts can be loaded. Native `mouse_passthrough` is intentionally disabled for this Glow window: winit implements cursor hit-test disabling on Windows with `WS_EX_TRANSPARENT | WS_EX_LAYERED`, and the layered style was observed to expose an unpainted/transparent OpenGL client area instead of the egui frame. The popup therefore prioritizes correct opaque rendering and non-activation at creation over native click-through. The popup owns the single dedicated Windows UI thread and single eframe/winit event loop used by SunSwitcher UI. The clipboard manager is rendered inside that same event loop/viewport instead of creating a second `run_native`, because winit allows only one event loop in this process. `sunswitcher` drives this shared UI runtime from the typed completion session and clipboard hotkeys, and `src/bin/completion_popup_probe.rs` remains the lower-level diagnostic probe that can display caret/fallback source information.

The same UI owner runs a separate focusless transient notification child viewport. Notification lifetime is read from the live `SettingsStore` when each message is shown; the persisted default is three seconds and the typed range is 1-60 seconds. A newer message replaces the current one immediately and restarts the deadline using the current setting. Notification state never replaces or clears autocomplete state. While suggestions are visible, placement is recomputed from the current suggestion viewport x/y/height so the notification follows autocomplete as its rows and position change; monitor-aware `popup_placement` keeps it adjacent and flips sides when needed. Without application UI it anchors from the current caret/fallback. While the clipboard/settings UI is visible, notification placement instead prefers the visible root viewport geometry, so focus/caret discovery in the settings child cannot make a confirmed Pause/Ctrl+Pause notification disappear. Notification requests emit `[notification]` diagnostics with the concrete message before the child viewport is rendered.

## Input and hotkeys

The clipboard-manager settings entry point is the UI owner for application preferences, but the settings surface itself is a dedicated resizable native egui child viewport on the same single eframe/winit event loop rather than an `egui::Window` constrained inside the clipboard viewport. It has its own vertical `ScrollArea`, so additional settings remain reachable when the content exceeds the current viewport height. Its native Windows caption is styled through the same DWM caption/text color owner and constants as the main Clipboard window. The Settings viewport has its own taskbar entry; opening it explicitly unminimizes, shows, and focuses the existing viewport so a minimized settings window remains recoverable from both the gear button and the Windows taskbar. It edits the six configurable hotkeys, enables/disables autocomplete, same-layout autocorrections, and automatic cross-layout keyboard switching, and edits notification timeout. Feature checkboxes persist immediately; hotkey capture and notification timeout use explicit confirmation. Hotkey action controls use painter-drawn vector refresh/confirm/cancel geometry rather than font glyphs, avoiding missing-glyph `?` rendering on Windows UI fonts; the refresh control uses a conventional two-arrow circular form. Built-in egui keyboard zoom is disabled for the application UI so Ctrl+Plus/Ctrl+Minus chords remain available to the hotkey recorder instead of resizing the interface. The shared `SettingsStore` is updated only after SQLite persistence succeeds, so UI and runtime never become competing settings authorities.

The default bindings remain plain Pause for correction Undo / selected-word forget and Ctrl+Pause for selected-word ignore, but both actions are now ordinary configurable `HotkeyAction` bindings. Windows may deliver physical Ctrl+Pause/Break as `VK_CANCEL` rather than `VK_PAUSE`; the typed hotkey contract canonicalizes that Ctrl-modified Windows identity to Pause before display/persistence, and runtime matching canonicalizes the observed event through the same contract. Settings therefore always renders `Ctrl+Pause`, while both Windows event forms execute the same binding even after the user assigns another shortcut and later records Ctrl+Pause again. Clipboard Current/Pinned, Completion Accept, Completion Next Word, Undo/Forget Word, and Ignore Word share one typed hotkey contract. The settings UI captures a new chord into a pending binding and requires explicit confirmation before persisting it; duplicate configured bindings are rejected. The low-level keyboard hook remains the primary capture input owner before ordinary SunSwitcher hotkey dispatch and before asynchronous modifier reconciliation: modifier transitions are retained in the hook-owned keyboard state while listening, the first physical non-modifier key completes the pending chord, captured keydowns skip normal modifier refresh and selection-intent tracking, Esc cancels, and mouse clicks are not part of capture and do not cancel it. Because a focused native egui settings viewport can still consume shortcut input before the low-level-hook path produces a usable pending chord, the settings viewport also polls physical VK down-state with `GetAsyncKeyState` at a short interval while listening and feeds only newly pressed non-modifier keys plus the current modifier state into the same canonical `HotkeyCaptureHandle::observe_key_down` contract. This fallback neither interprets nor persists bindings separately; both input paths converge on the same pending binding and explicit confirmation. The poller samples the Windows Ctrl+Break VK_CANCEL state explicitly and prioritizes VK_CANCEL/VK_PAUSE before ordinary reported keys, so recording Ctrl+Pause again after another binding cannot be stolen by a simultaneously reported OEM key. `[hotkey-capture]` diagnostics record listening/cancel/captured transitions and the settings fallback source when it wins. Runtime hotkey classification reads the shared live settings snapshot, so confirmed changes apply without restart and without SQLite I/O in the keyboard hook. Persistence returns a typed confirmed word outcome for forget/ignore operations, and only that outcome produces the transient notification with the concrete word.

The configurable hotkey contract reserves the fixed unmodified autocomplete controls (Esc, Up, Down, Delete). Settings conflict validation must reject those bindings for every configurable action so recording a shortcut cannot silently replace dismiss/navigation/delete behavior.
Runtime classification first resolves every configured SunSwitcher binding from hook-owned keyboard state. If no binding matches a physical non-modifier key, modifier state is reconciled from Windows and the configured bindings are retried once before ordinary key classification, recovering from stale hook-owned modifier bits without weakening the first-pass chord semantics. Unmodified Ignore/Undo bindings are queued out of the low-level hook immediately after their recognized keydown, while modified bindings wait until all chord modifiers are physically released; configurable chords such as Ctrl+W and Ctrl+Pause therefore never perform selection capture or replacement while Ctrl/Alt/Shift/Win remains held, and plain Pause does not depend on a later Pause key-up. Their recognized keydown preserves explicit mouse/Shift selection intent. Deferred selected-word actions use the existing clipboard-preserving explicit-selection capture when UI Automation exposes no selection; if explicit selection was proven but safe capture fails, the action fails closed instead of falling back to unrelated tracked text. Ignore still refreshes the lexical snapshot before rechecking the source, so suppressing valid source spellings such as jr or yt can immediately expose the corresponding cross-layout replacement and confirmed mutations emit the transient notification.

Live completion normally activates after three characters in the current token; after a completed word and trailing space, context-only sequence suggestions may remain active even with an empty current prefix. The production `sunswitcher` uses the live correction session, where strong unfinished wrong-layout prefixes can be replaced before boundary and completion is immediately refreshed from the corrected current prefix. An active live-prefix switch continues scoring later prefix evidence and reverses only when the opposite layout clears the stronger hysteresis margin, so close scores keep the visible layout stable. Unmodified Up/Down changes selection; unmodified **Tab** accepts the complete selected suggestion while Enter always passes through to the foreground application; Alt+Right accepts exactly the next word plus its separating space; unmodified Delete removes the selected prediction; and unmodified Esc dismisses. After a proven Alt+Right insertion, completion tracking advances to the accepted word, accepted words update user-word recency, the accepted context sequence is persisted into `text_history`, and sequence suggestions refresh immediately. After a proven automatic correction or Double Shift layout replacement of the previous word, completion context is refreshed to the replacement's canonical word instead of being left on the raw physical spelling or invalidated, so sequence suggestions can continue from the corrected/translated word. The remainder that was visible in the selected row before acceptance is protected as the prefix of the refreshed top row: ranking may extend it with newly predicted words, but may not change those already-visible words. Repeated Alt+Right therefore never inserts an unseen replacement word; Up/Down deliberately releases that protection and chooses another path. While completion is active, the physical Alt modifier used to form Alt+Right is owned by SunSwitcher: its down/up pair is suppressed from downstream hooks, while the internal keyboard state still records Alt so Right can resolve to `AcceptNextWord`. The accepted word is injected as Unicode only; no synthetic Alt release/repress is sent to the foreground application. Delete removes the row immediately from the current session; learned multi-word rows delete their exact `text_history` source, while single-word candidates persist a completion-only suppression so dictionary/user lexical authority is not destroyed. Keyboard runtime resolves a completion command before calling the downstream hook chain: handled command keydown/up pairs are SunSwitcher-only; only `Pass` from an inactive/non-consuming completion session is forwarded. Double Shift is a separate layout-switch command: two otherwise plain **physical** Shift taps within 400 ms trigger on the second Shift release; SunSwitcher/foreign injected keyboard transitions never participate in the gesture. A freshly owned typed layout span wins first because it is the strongest proof of the text immediately before the caret and avoids UIA/clipboard work; mouse or navigation selection invalidates that ownership before Double Shift. With no owned span, Double Shift first probes for an explicit selection with clipboard-preserving Ctrl+Insert, which is layout-independent and safe even when UI Automation exposes no selection. Shift+navigation, completed mouse-drag selection, and mouse double-click selection are tracked as typed user-selection intent. Existing explicit selections try Ctrl+Insert first, then Ctrl+Shift+C for terminal-style copy bindings; Ctrl+C is allowed only when UIA itself proves the selection, so it is not sent on intent alone. A second safe Ctrl+Insert probe distinguishes a selection that remained active from one that collapsed after copy; retained selections are replaced directly, while collapsed-at-start selections are reconstructed with the captured character count before the same Delete+Unicode replacement. Without an owned span or explicit selection, the previous-text fallback creates one bounded 64-character backward selection with physical Shift+Left instead of relying on application-specific Shift+Home semantics. After the synthetic Shift+Left, UIA-selected text is diagnostic only because browser UIA ranges can report a partial selection that is not the actual editable selection. The previous-text fallback uses clipboard-verified safe Ctrl+Insert first and then Ctrl+Shift+C; Ctrl+C is deliberately not used for this synthetic previous-text probe, so a terminal that refuses copy shortcuts fails closed instead of receiving an interrupt/printable C. If the synthetic backward selection remains active, SunSwitcher leaves that exact active chunk selected and applies the replacement as `leading copied text + transformed target + suffix` in one Delete+Unicode batch instead of collapsing the browser selection and selecting backward again. If copy collapsed the selection to the start, SunSwitcher advances by the captured caret-step count. From that restored original caret, SunSwitcher finds the trailing non-whitespace range (including layout punctuation), moves left across preserved trailing whitespace, selects only the target with Shift+Left, replaces it, and moves right across the preserved whitespace. This keeps capture/replacement relative to the proven original caret and avoids per-character clipboard probing. The owned `InputBuffer` layout span retains punctuation and trailing whitespace through Double Shift, remains owned after a successful transform for repeated switching in the opposite direction, and is replaced through the same Backspace+Unicode effect path used by automatic correction. Once ownership is unavailable, clipboard capture is used only after SunSwitcher has evidence of an explicit selection from UIA, keyboard Shift+navigation, mouse-drag, or mouse double-click selection intent, or has itself created the bounded Shift+Left backward selection. The selected/previous text transform returns both transformed text and target language. Captured selections that remain active are replaced by clipboard-backed Ctrl+V paste instead of Unicode replay, so CRLF and multi-line content survive application-specific text input paths; terminal selections that collapse on copy are reconstructed from the proven caret anchor with Shift+Right before that same replacement. The previous-text fallback either replaces the retained active backward chunk directly or reconstructs the trailing non-whitespace range relative to the restored original caret via Left trailing offset, Shift+Left target selection, replacement, and Right trailing-whitespace restoration; line-start normalization and Ctrl+word-navigation are not used. Only after the text effect succeeds does SunSwitcher request the matching installed foreground keyboard layout through `WM_INPUTLANGCHANGEREQUEST`, so the next physical keystroke uses the same language as the converted text. Double Shift diagnostics use the `[double-shift]` diagnostic prefix and report tracked-span invalidation from mouse/navigation input, the chosen capture path, UIA observations before/after copy, clipboard source/range counts, and the final replacement path; the diagnostics describe observed state and never branch on application identity. The Double Shift editing effect is deferred from the second physical Shift key-up hook callback onto the hook thread message queue: the low-level hook never performs the multi-step SendInput/clipboard capture synchronously, so injected selection/copy events are processed only after the hook returns and Windows finishes the physical Shift release; a still-held physical Shift at deferred dispatch fails closed instead of editing under ambiguous modifier state. Backward chunk capture may include CRLF when the bounded selection crosses a line boundary; caret restoration treats each CRLF pair as one navigation step and still derives only the trailing non-whitespace target at the original caret. Synthetic text-range selection uses physical left Shift with extended Left/Right navigation rather than generic VK_SHIFT or line-start shortcuts; navigation-cluster keys keep the Windows extended-key identity. Safe probing uses physical left Control plus extended Insert (Ctrl+Insert); Ctrl+Shift+C is the terminal-style safe fallback; Ctrl+C is reserved for UIA-proven existing selections only, so neither unknown explicit-selection probing nor synthetic previous-text probing can degrade into terminal interrupt/printable C/С behavior. Any explicit input invalidation clears layout-span ownership even when that span came from a previous Double Shift replacement; navigation therefore cannot leave a stale transformed span eligible for a later gesture. A tracked span that exists but has no layout transform is dropped and Double Shift continues into the normal capture fallback instead of ending the gesture. Clipboard manager defaults are handled by the same Windows keyboard runtime: Ctrl+Shift+Num+ opens the text history window on the Pinned tab, and Ctrl+Shift+Num- opens it on the Current tab. The manager stores the foreground window captured at hotkey time, switches the shared SunSwitcher UI viewport into a clipboard-history mode with Current/Pinned tabs, case-insensitive filter, top-row numeric insert buttons, context-menu Pin/Unpin, and a settings view for hotkeys, feature toggles, and notification timeout. Text entries selected for insertion are first copied to the system clipboard and then pasted with Ctrl+V into the captured foreground window; insertion fails closed when no target exists or Windows refuses to focus it. The listener owns the resulting text-history/copy-count update so one manager action is not counted twice; guarded image copy-back updates its entry directly. These bindings remain defaults; confirmed settings changes replace them live through the shared `SettingsStore`.

## Clipboard manager window

The clipboard manager uses the shared SunSwitcher egui viewport, but when history is visible it switches that viewport into a normal movable/resizable decorated window (`Decorations(true)`, `Resizable(true)`, explicit on-screen position, and focus). Closing via X, pressing Escape, or minimizing the native window hides the manager back to tray instead of shutting down the process; minimize is converted into a parked, explicitly unminimized 1x1 root event pump so tray/hotkey reopen and autocomplete child rendering remain live. Because that same native root viewport is the persistent eframe event pump for clipboard and autocomplete child viewports, every root close request is canceled even if another close event arrives after the manager was already parked; only explicit global shutdown is allowed to close the root viewport. A persistent Win32 tray icon is created on a separate message-window thread through `Shell_NotifyIconW`; its ICO bytes are embedded into the executable at compile time and decoded into an `HICON` with an `IDI_APPLICATION` fallback, and clicking it opens the Current clipboard tab. The root/window PNG icon is likewise embedded with `include_bytes!`; release builds therefore require no sibling `assets/` directory. MSVC builds enable static CRT linkage, so the distributable is one `sunswitcher.exe` plus only normal Windows system DLL dependencies. Clipboard history rows are cached until an explicit state change (listener history notification, tab/filter change, pin/reorder, or other manager mutation) invalidates them; the open manager does not poll SQLite or reread image BLOBs on a timer. Clipboard rows use a dark autocomplete-style theme with yellow accent borders and a yellow-accent scrollbar whose idle solid handle uses a brighter muted-gold fill instead of blending into the dark track; Current/Pinned tabs remain fixed-size at the top, and the filter field plus right-aligned gear settings button live on the bottom row. Ctrl+Shift+`+` switches the open manager to Pinned and Ctrl+Shift+`-` switches to Current, consuming those egui shortcuts so the manager does not zoom. Left-clicking a row copies its text or image to the system clipboard and hides the window; number buttons or number keys 1-9 also insert text rows into the foreground target captured when the manager was opened. Row pinning is available from the row context menu instead of always-visible Pin buttons. The same row menu exposes `Clear` on both Current and Pinned; Current additionally exposes `Clear All`, which removes all saved clipboard entries (including pinned entries) while deliberately leaving adaptive learning state untouched. Hovering a previewable row opens a separate preview viewport the same size as the manager window, positioned to whichever side fits the current monitor; the preview reads the latest hovered row from shared state without hiding/recreating the viewport when moving between previewable rows, refreshes immediately only when the preview entry changes, keeps activity alive only from the hovered source row or the preview viewport itself (with the hide delay bridging the pointer gap), evaluates current-frame source-row hover before expiry so a scheduled wakeup cannot expire/restart the same preview while the pointer is still on its row, inherits the already-applied manager style instead of resetting egui styles each preview frame, and uses a bounded 750 ms keepalive/expiry repaint instead of a continuous preview repaint loop while hover is stable. The preview shows full text or DIB image content (including standard 32-bit BI_BITFIELDS masks whose mask table precedes pixels), renders preview text and timestamp as selectable labels in an entry-scoped egui id with shared dark/yellow selection colors so text selection does not leak between different preview rows, remains alive while the pointer is over either the row or preview, and disappears shortly after both are left. The main egui viewport carries the same icon as the tray icon; one tray left-click release opens Current and carries the previously foreground target into the manager for numbered insertion, while right-click exposes Exit and requests the global hook/UI shutdown. Tray and hotkey open paths emit `[tray]`, `[hotkey]`, `[ui-command]`, `[ui-frame]`, and `[ui-viewport]` diagnostics so a non-opening manager can be localized to tray receipt, hotkey dispatch, shared-state serial update, UI-frame observation, or native viewport command delivery. The native clipboard window title bar is tinted through best-effort Windows DWM attributes to match the dark UI. Autocomplete suggestions are always rendered in a separate dark/yellow suggestion viewport capped to eight visible rows. Popup handle updates repaint only when the shared suggestion state actually changes, so a stable active completion session does not spin the UI event loop. Clipboard/adaptive token extraction uses an allocation-free ASCII scanner with a Unicode fallback that preserves the same word-character and edge-trim semantics. When the clipboard manager is open, autocomplete updates only request repaint and never reconfigure the root viewport; the child suggestion viewport is anchored from the clipboard root viewport itself instead of depending on UIA/MSAA caret discovery from egui's filter field. When the clipboard manager is hidden, the shared root viewport stays alive as a 1x1 off-screen non-taskbar event pump instead of being hidden; autocomplete updates therefore only mutate shared state and request repaint, and the child suggestion viewport is anchored from the foreground caret/fallback. On every non-modifier keydown, the keyboard runtime reconciles left/right physical modifier state from Windows before classifying text input, so a generic Ctrl/Shift hotkey transition cannot leave stale command modifiers that make normal typing look like command-modified input. Modifier reconciliation preserves generic and side-specific Ctrl/Shift/Alt/Win states so Ctrl+Shift clipboard hotkeys do not leave stale command modifiers and Alt+Right completion remains active. Alt+Right, Up/Down, and Tab operate on the latest shared PopupState without focusing the suggestions window; physical modifier reconciliation is deferred for recognized completion hotkeys so Alt+Right is not converted into a plain Right navigation invalidation; stale Ctrl/Shift is refreshed before clipboard plus/minus hotkeys are accepted so normal + and - typing is not stolen after opening the manager. Clipboard manager row copy and 1-9 insertion copy selected text to the clipboard without the internal-mutation guard, so the normal clipboard listener records the text into history and adaptive learning/user-word and sequence ranking can observe copied text through the bounded 40 KiB batch-learning path. Large clipboard texts are still stored in clipboard history subject to history payload limits; 1-9 then injects Ctrl+V instead of replaying Unicode characters, so multiline snippets keep their line breaks and injected text is not reprocessed as user typing.
